# Canonical motion learner

This is a real, bounded CPU reinforcement learner inside Nationals-work3, not another physics model. Python's PyTorch actor-critic consumes the existing 34-value sensor/reference observation; optional deadline context also uses public planner metadata at reset. It sends four bounded reference actions through `MotionEnvironment` to the original Simulator and source-checked iraLIB C++ controller. The JavaScript plant/controller runs at 100 Hz; decisions normally run at 20 Hz. The separate historical failure predictor is not used.

## Run explicitly

From the repository root, reuse the existing pinned `torch==2.8.0` CPU environment:

```powershell
node roboproof/cli.js motion-check
& 'roboproof/gpu/.venv/Scripts/python.exe' -m roboproof.motion_learning.train --seed 42 --seed-count 3 --updates 8 --max-steps 4096 --max-seconds 180
node roboproof/cli.js motion-compare-learned
node roboproof/server.js 8766
```

Open the existing dashboard's **Motion lab**, click **Refresh training history**, then inspect the controller/untrained/learned comparison. Select **Learned PPO · explicit experiment** to run a new task and open its recorded actions in the original 2D/3D Simulator. The default is still controller-only. A successful individual experiment does not certify learned improvement.

When a consumed independent final is linked by `independent-final.json` inside the run directory, the same refresh displays its checkpoint-bound counts and regressions. The reader verifies result/audit hashes, all case identities, aggregates and strict acceptance calculations. Changed source/runtime is labeled historical. This is read-only local audit evidence, not external custody, and cannot enable policy promotion; missing or inconsistent evidence fails closed. To transfer this view, copy both the learning run and its referenced consumed `roboproof/runs/motion/holdout/<UUID>/` directory without modifying files. The old `motion-compare-learned` command uses the already-inspected historical v2 corpus, not a new independent final.

Controller success was 87/128; learned success was 75/83/81 with 12/5/8 controller-success regressions. All strict gates failed despite effort-proxy reductions. Training and implementation tests are real, but no accepted movement-improvement or AMD result is claimed. The default budget is three independent seeds, at most eight updates and 4,096 policy steps per seed, with a shared 180-second collection deadline. Environment access has its own timeout; one already-started bounded PPO update/checkpoint/teardown may finish after the collection deadline. There is one bridge worker and one CPU training thread. No cloud call, firmware command, AMD provisioning or model download occurs. The browser never launches a Python process, installs dependencies, or starts training on load. A CLI run is explicit and bounded; refreshing reads disk only.

## Algorithm and boundaries

- Separate actor and critic each have two 32-neuron tanh hidden layers. The actor has eight Beta concentration outputs (four alpha/beta pairs); the critic has a scalar value head. Deterministic evaluation uses the Beta mean mapped to `[-1, 1]`; stochastic rollouts use the distribution itself. This is a small deep RL model, not an LLM. Exported inference still contains only the two actor layers and Beta head.
- PPO clipped likelihood ratio (0.2), four optimization epochs with balanced minibatches of at most 64 rows, separate Adam parameter groups at actor learning rate 0.001 and critic rate 0.0003, per-network gradient norm cap 0.5 and entropy coefficient 0.001. Diagnostics average minibatch statistics by row count, not equally across different-sized minibatches. Fixed engineering-unit observation scales clip to ±10 and are not fitted on evaluation data.
- History records pre-clipping combined, actor and critic gradient norms. The combined post-clipping norm is not itself capped at 0.5; each network is clipped separately. Negative continuous entropy is valid, not a failed probability calculation.
- The original Simulator's canonical reward and physical success criteria are unchanged. The default declared training objective `finite-deadline-pose-effort-v2` normalizes measured distance progress by requested task length, adds signed measured heading progress, multiplies the canonical effort penalty by 100, doubles success/fault terms, and charges -2 for task-deadline expiry. These are training-only reward experiments, not new physics or relaxed pass thresholds. Both learning and canonical rewards are retained; reward increase alone cannot unlock a policy.
- The actual task deadline is intrinsic to this finite-horizon objective, so its expiry suppresses value bootstrap. Collection-budget interruption discards the partial rollout instead of creating a fake terminal episode. `canonical-v1` remains a declared comparison profile with continuing-task truncation bootstrap. Default pose/effort objectives use gamma 0.995 and GAE lambda 0.98; canonical uses 0.99/0.95. Advantages never cross resets. Shortened final cadence uses the policy-step discount; no exact continuous-time discount claim.
- Experimental `--objective finite-total-return-pose-effort-v3` preserves the v2 reward but uses gamma 1 and GAE lambda 1 on complete finite episodes. This gives early actions the full episode return instead of attenuating terminal credit through the old trace. Intrinsic deadlines remain terminal and interrupted collections remain discarded. Run/checkpoint metadata declares the estimator, and mismatched declarations/resume configurations fail closed. This is an estimator experiment, not a changed pass criterion or guaranteed improvement.
- Curriculum `mixed-reach-v2`: four short near-forward episodes, then a repeating varied-heading/direction, randomized-physics, easy, randomized-physics mix. Hard physical variation begins at episode 5 (zero-based), not episode 24; two of the first eight episodes use it, and easy worlds stay present. Supported mass/traction/slip/battery-resistance bounds are unchanged. The frozen v1/v2 seeds and tasks are excluded. Evaluation does not select hyperparameters or checkpoints. Initial-policy evidence is retained for each seed.
- Explicit `--curriculum field-reach-v4` adds larger field goals, sampled goal headings, all six supported physical-parameter ranges and recurring ±60-inch boundary targets. Parser bounds do not prove every requested task is physically reachable or meets its deadline; failures stay in evaluation. `broad-pace-v1` initialization broadens pace exploration while keeping residual corrections conservative; `conservative-v1` is available for declared comparisons.
- Optional `--policy-regularization public-deadline-residual-v1` adds a squared pace shortfall loss (weight 1) against a known-reference deadline estimate with a two-second settling reserve, plus residual-only KL to symmetric Beta(60,60) (weight 0.02). It is training regularization, not a deployment guard, a physical feasibility promise or an evaluator-based action oracle. Public trajectory duration/time and the declared task deadline supply the pace target; physical truth does not. Raw actor inputs stay at 34. Default `none` keeps the previous loss; source/configuration checks prevent incompatible resumption. Recorded prior losses are explicitly training-only diagnostics.
- Optional `--feature-transform reference-frame-v1` converts known reference errors, velocities, offsets and goal-error vectors to the reference frame and represents relative reference/robot heading using sine/cosine. This derives 35 engineered features from the same 34 raw values; it adds no sensor or physical truth. Absolute pose remains available for field context, so this is not full field/rotation equivariance. The default `identity-v1` and older 34-input exports remain supported. New exports declare feature count/version; unsupported versions or dimensions fail closed. Python/JavaScript inference parity and exact original-engine action replay are tested.
- Experimental `--feature-transform history-context-v1` stacks four chronological reference-frame observations and freezes the first raw target-error vector (indices 10..13). Its 144 derived inputs still come only from the existing 34 values. Padding repeats the first observation; memory resets at every episode and bootstrap previews do not advance it. Four decisions span 150 ms at the default 20 Hz cadence. This is a finite history window, not a recurrent model, a new sensor or a guarantee of slip observability. PPO minibatches use the exact inputs collected during rollout rather than reconstructing incompatible history. Exported actors declare their history/context sizes; the original runner resets them before each task and recorded actions still replay without inference.
- Training history now separates actor/critic losses, differential entropy, approximate KL, clip fraction, critic explained variance, sampled action mean/std/boundary fraction and curriculum-stage counts. Entropy may be negative for a continuous distribution; constant returns produce null explained variance. These are diagnostics, not improvement gates or actual executed-action saturation measurements. The dashboard shows latest diagnostics, and labels older records without them as not recorded. Non-deterministic wall timings are not inserted into resume/replay histories.
- No obstacle observation, camera input, independent slip sensor, pickup action or game reward is present in this contract. This is reference adaptation around LTV-LQR and wheel PI/feedforward, **not general obstacle navigation, learned motor control, or learned VEX scoring**. Sensor ambiguity and limited residual bounds can prevent improvement; a small smoke run is not a trained product.

Algorithm references: [original PPO paper](https://arxiv.org/abs/1707.06347), [PyTorch 2.8 distributions](https://docs.pytorch.org/docs/2.8/distributions.html), [PyTorch reproducibility limitations](https://docs.pytorch.org/docs/2.8/notes/randomness.html). No third-party RL implementation was installed or copied; the existing PyTorch dependency is reused.

The duration comes from the original planner at episode reset, not simulated physical truth. This preserves the distribution mean and stochastic support while reducing variance. Each collected transition records its factor; PPO reconstructs the same sampling distribution for likelihood ratios and entropy. Deterministic JSON inference still uses the original Beta mean. The factor and sampling definition are bound to the checkpoint configuration, and changing either rejects resume.

## Improvement is a separate gate

`motion-compare-learned` freezes all committed policies and compares the existing controller, each seed's initial untrained actor, and each learned actor on the same 24 frozen worlds. It preserves every failure, position/heading error, elapsed time, contact duration and electrical effort proxy; the proxy is not calibrated energy consumption.

The existing predeclared gate requires higher success than both controller-only and untrained policy, zero baseline-success regressions, no per-world contact increase, and at least 5% all-world mean time or effort improvement. Three independent training seeds must each pass. A gradient update, lower training loss, a single favorable seed or higher training reward does not unlock **Use verified policy**. The first seed is the predetermined experimental policy; there is no best-seed selection using the frozen corpus. The experiment option remains explicit even when the improvement gate fails.

After inspecting this frozen benchmark, never tune against its individual cases and reuse it as fresh evidence. Further development should use training/development-only worlds and reserve an additional untouched final corpus before claiming new held-out improvement. Physical calibration, game mechanics, genuine AMD training, perception and hardware safety are separate future gates.
